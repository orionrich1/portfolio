- **채용 담당자**로서, 10초 안에 **이 지원자의 주 역할(프론트 vs 백)** 과 **차별점(AI 활용)** 을 이해하고 싶다.
- **동료 개발자**로서, 프로젝트마다 **문제 → 접근 → AI·도구 활용 → 결과** 흐름이 보이길 원한다.
- **본인(포트폴리오 오너)** 으로, 공백기·전향에 대한 설명 없이 **실무·교육·AI 역량**이 한 흐름으로 읽히길 원한다.

#### 2. About Me (서사 3블록)

기획 원안을 **논리 순서**로 고정한다.

1. **디자인·퍼블**: 「디자인 전공으로 픽셀 단위의 디테일을 배웠고, 16개월간의 퍼블리셔 실무를 통해 웹 표준과 반응형 환경에 능숙해졌습니다.」
2. **백엔드 학습**: 「이후 백엔드 메커니즘을 7개월간 깊이 있게 학습하며 데이터의 흐름을 이해하는 개발자로 성장했습니다.」
3. **AI 워크플로**: 「현재는 Cursor와 Claude 등 최신 AI 툴을 비서처럼 활용하여, 프레임워크의 제약을 넘어 압도적인 속도로 고퀄리티 결과물을 만들어내는 데 집중하고 있습니다.」

**기획 보완**:  
- 「디자인 **전공**」은 **실제 학력·이력과 일치**해야 한다. 학원·실무 위주라면 문구를 「디자인 **배경**」「시각 디자인 **실무**」 등으로 완화한다.  
- 「압도적인 속도」는 **검증 가능한 사례**(기간 단축, 반복 작업 자동화) 한 줄을 붙이면 신뢰가 올라간다.

#### 3. Projects (코드모아·펫케어 공통 골격)

각 프로젝트 카드에 **아래 3블록**을 같은 순서로 둔다. 기존 GitHub / Live Demo 링크는 유지.

| 블록 | 필수 메시지 | 기획 삽입 문장(예시·조정 가능) |
|------|-------------|--------------------------------|
| **UI/UX Focus** | Figma·직접 설계·퍼블 경험 | 「디자인 **배경**을 살려 Figma에서 UI를 설계·검토하고, 퍼블리싱까지 일관되게 맡았습니다.」※ Figma 산출물·링크가 있으면 **수락 조건**에 포함 |
| **AI Collaboration** | 프롬프트·도구로 속도·품질 | 「복잡한 Vue/React 상태 관리·API 연동은 Cursor·Claude 등과 **프롬프트 설계**를 병행해 구조를 정리하고 구현 속도를 높였습니다.」 |

**정합성 주의**:  
- **Vue/React**: 실제 저장소·데모 스택과 맞는 프레임워크만 쓴다. 팀 프로젝트가 Thymeleaf/JSP 중심이면 「템플릿·SSR 화면」「점진적 인터랙션」 등 **사실에 맞게** 수정한다.  
- **「개발 속도 200%」** 같은 **배수 표현**은 근거(이전 대비 기간, 측정 방법) 없으면 오히려 역효과. 권장: 「체감상 이전 대비 구현·리팩터링 시간을 크게 단축」 또는 **구체 일정·범위** 한 줄.

## 취업용 포트폴리오 개선 진단

**목적**: 기능 적합을 넘어, 채용 담당자·동료가 **신뢰·완성도·전달력**을 느끼도록 과거에 지적된 지점을 정리한다.

**최신 조치 요약**: 루트 **README**, **GitHub Actions**(`npm run build`), **메타·OG**(`<title>`·`description`·OG는 **히어로 영·한 카피**와 동기화), **외부 링크 `rel`**, Projects **빈 `h2` 제거**, **Tailwind PostCSS 단일 파이프라인**(`src/index.css` + `tailwind.config.js` 색상 `#121212` / `#A3E635` 통일), 중복 **루트 `index.js` 스크립트 제거**·단일 원본 주석, **푸터 연도·카피·케이스 스터디** 등은 반영됨. 아래 표는 **초기 진단 기록(참고)** 이다.

### 1. 저장소·운영 인상

| 현상(초기) | 왜 아쉬운가 | 권장 방향 |
|------|-------------|-----------|
| 루트 **README**가 없거나 빈약함 | 클론 후 실행·빌드·폴더 역할을 추측해야 함 | 한 줄 소개, Node 권장 버전, `npm run dev` / `npm run build`, 배포 URL |
| **CI** 부재 | 빌드가 통과한다는 신호가 저장소에 안 보임 | GitHub Actions로 `npm run build` 최소 연동(선택) |

### 2. 검색·공유·브랜딩

| 현상(초기) | 왜 아쉬운가 | 권장 방향 |
|------|-------------|-----------|

| 타이틀만으로 **한 줄 가치 제안**이 안 보임 | 검색 스니펫·북마크 시 차별이 약함 | 백엔드·Spring 등 키워드를 자연스럽게 한 문장 요약 |

## 카피 진단·개선 권고 (기획)

**리브랜딩 v2** 론칭 후에는 히어로·About·Projects 톤이 `## 리브랜딩 기획 (v2)` 로 대체되므로, 본 절 중 **겹치는 항목은 폐기**하고 메타 동기화·문장 호흡 등만 참고한다.

아래는 **현행 `src/index.html` 문구**를 기준으로 한 진단이다. 톤은 유지하되, **채용 담당자가 읽을 때** 어색하거나 신뢰를 깎는 표현을 골랐다. 반영은 디자이너/본인 검토 후 개발자가 적용한다.

**메타·브랜딩 동기화**: 본문 **히어로 헤드라인·한 줄 소개**가 바뀌면 같은 작업에서 `src/index.html` 의 `<title>`, `meta name="description"`, `og:title`, `og:description` 을 함께 갱신한다. (README 첫 문단도 동일 톤으로 맞춘다.)

## 전역

### 목표

- 방문자가 **한 페이지**에서 소개·프로젝트·스킬·경력을 빠르게 파악할 수 있다.
- **리브랜딩 v2** 적용 시: **AI 보강 프론트엔드 + 디자인 엣지**를 첫 화면에서 인지시키고, 백엔드 역량은 **API·데이터 흐름 이해·병목 예방** 관점에서 **보조 스토리**로 묶는다. (상세는 `## 리브랜딩 기획 (v2)`)
- 시각·간격·애니메이션은 **`DESIGN.md`** 와 이 명세의 수락 조건을 우선한다.

### 기술·구조 (이 저장소 기준)

- **엔트리**: `src/index.html` → Parcel이 번들 (`npm run dev` / `npm run build`)
- **스크립트**: 페이지 내 **인라인 스크립트**로 GSAP·스크롤 UX 등 처리. 루트 `index.js`는 **엔트리에 포함되지 않으며** 주석으로 단일 원본을 안내한다.
- **스타일**: `src/index.css`(Tailwind + PostCSS 빌드) — `tailwind.config.js`의 `cBlack`/`cMain`이 화면 토큰과 일치한다.
- **정적 자산**: `img/`, `favicon.ico` 등

### 운영 원칙

- 외부로 나가는 링크(GitHub, 데모 URL)는 깨지지 않게 유지한다.
- 연락처(이메일·전화) 변경 시 HTML·스크립트 선택자 일관성을 유지한다.
